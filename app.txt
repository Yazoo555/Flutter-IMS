1. WHAT THE APP IS ABOUT
================================================================================

FYP Calendar is a dedicated "FYP Command Center" for final-year students of
Cohort 11. It is NOT a generic calendar or a renamed routine app — every
feature is built around the official FYP journey:

  • Understand the complete FYP timeline (Week 1 → Week 50) with official
    week labels, including special periods (Dashain Holiday, Non Teaching
    Weeks) transcribed verbatim from the source spreadsheet.
  • See the next important deadline with a live countdown.
  • Track the 9 official milestones/gates (Gate 1 → Gate 3 / Resit) with
    status (Not Started / In Progress / Submitted), portal-opening windows
    and preparation checklists.
  • Manage personal FYP tasks (List + Kanban) linked to milestones.
  • Record supervisor / reader / team meetings.
  • Self-report project progress and compare it against the official 75%
    Internal Defense readiness target.
  • Review analytics: milestones done/remaining, tasks done/remaining,
    upcoming deadlines, overdue tasks, deadline health.
  • Configure reminders, theme (System / Light / Dark) and project info.

The experience flows top-down on Home:
  TODAY → CURRENT FYP PHASE → NEXT DEADLINE → MILESTONE PROGRESS →
  PERSONAL TASKS → FULL FYP TIMELINE (journey strip)

All official dates come from ONE centralized dataset
(lib/data/fyp_calendar_data.dart), transcribed from
FYP_Calendar_Cohort11_Context.md. Official definitions are immutable;
the app stores only user state (completion flags, statuses, custom items).

3. THE OFFICIAL FYP TIMELINE (Cohort 11)
================================================================================

Calendar range : Mon 3 Aug 2026 (Week 1) → Sun 12 Sep 2027 (Week 50)
Week numbering : "Week N" on Mondays, EXCEPT special labels:
                 "Dashain Holiday" (5 weeks, 11 Oct – 16 Nov 2026) and
                 "Non Teaching Week" (three December weeks: 7/14/21 Dec 2026).
                 Special weeks are never numbered; numbered weeks stay 1–50.

GATES & MILESTONES
  Gate 1        Title Submission (Google Form)      31 Aug 2026
  Gate 2        Proposal Deadline                  25 Sep 2026
                (portal opens 18 Sep — 9 working days prior)
  Milestone 2   Literature Review (Plag check)     25 Dec 2026   portal 14 Dec
  Milestone 3   Artefact Design and Test Plan      29 Jan 2027   portal 21 Jan
  Milestone 4   Professionalism section of report   5 Mar 2027   portal 22 Feb
  Milestone 5   Draft report + advanced artefact    9 Apr 2027   portal 30 Mar
  Milestone 6   Final Report Submission            18 May 2027   portal  3 May
  Milestone 7   Poster and Code Submission         27 May 2027
  Gate 3        Resit Submission (CONDITIONAL)      6 Jul 2027

ASSESSMENT PERIODS
  Proposal Defense                4 Oct & 7 Oct 2026
  Internal Project Defense       18–23 Apr 2027   (project ≥ 75% complete)
  Poster Presentation / Viva     19–26 May 2027
  Resit Poster Presentation/Viva  7–9  Jul 2027

BOARD / RESULTS
  Approximate results             22 Jun 2027
  Resit results                    3 Aug 2027

HOLIDAYS / NON-TEACHING
  Dashain Holiday                11 Oct – 16 Nov 2026 (~5.5 weeks)
  Non Teaching Weeks             7, 14, 21 Dec 2026 (deadlines still apply)

PORTAL PATTERN: every milestone portal opens ~9–10 days before its deadline.
The app models this explicitly (portal event ↔ relatedMilestoneId ↔ deadline)
and shows a Portal → Prepare → Deadline strip in event details.

KEY PROCESS WARNINGS (surfaced contextually in the app):
  1. Proposal must be supervisor-APPROVED (Proposal Feedback Sheet) before
     the 25 Sep deadline; then fill the PRF in the portal.
  2. Internal Defense requires ≥ 75% project completion.
  3. Use the portal window — don't wait for deadline day.
  4. Dashain creates a long teaching gap right after Proposal Defense;
     plan literature review work accordingly.

4. ARCHITECTURE
================================================================================

main.dart (FypCalendarApp)
  └─ loads ThemeMode from StorageService (system default)
  └─ AppShell(themeMode, onThemeModeChanged)
       ├─ 6 destinations: Home, Calendar, Milestones, Tasks, Progress, Settings
       ├─ Bottom navigation bar on mobile (< 900 px)
       ├─ Sidebar with theme switcher on desktop (≥ 900 px)
       └─ IndexedStack preserves each screen's state

Data flow (one direction, easy to follow):
  fyp_calendar_data.dart  ── official, immutable
        │
  FypRepository  ── merges official data with StorageService user state:
        │            • completed-event ids   → FypEvent.copyWith(isCompleted)
        │            • milestone progress    → overlay status/percent/notes
        │            • tasks / meetings / checklists / project info / progress
        │            • queries: nextDeadline(), overdueEvents(), eventsToday(),
        │              importantUpcoming(), milestoneStats(), taskStats()
        ▼
  Screens (StatefulWidget + Future loads; repository never leaks storage)

Storage keys (SharedPreferences):
  fyp_completed_events    Set<String>  official event ids marked done
  fyp_custom_events       JSON list    user-created events
  fyp_milestone_progress  JSON map     per-milestone status/percent/notes
  fyp_checklist_items     JSON list    personal preparation checklist
  fyp_tasks               JSON list    personal tasks
  fyp_meetings            JSON list    meetings
  fyp_project_progress    JSON         self-reported overall % + breakdown
  fyp_project_info        JSON         title/description/supervisor/reader/team
  fyp_theme_mode          String       system | light | dark
  fyp_notif_enabled       bool         master reminders switch
  fyp_notif_deadlines     bool         deadline reminders
  fyp_notif_portals       bool         portal-opening reminders
  fyp_notif_meetings      bool         meeting reminders

Robustness: every JSON load is wrapped in try/catch — malformed local data
is dropped and defaults are used instead of crashing. ProjectProgress clamps
all percentages to 0–100 at the model layer.

7. DESIGN SYSTEM
================================================================================

Semantic colors (AppColors):
  primary indigo #4F46E5   deadline red      assessment orange   portal amber
  session green  supervisor teal    board purple      holiday neutral gray
  milestone violet   googleForm sky    status: completed green / in-progress
  blue / not-started gray
  Light + dark palettes defined per role — no hardcoded colors in screens.

Typography: Inter via google_fonts; contextual scale (displayLarge … caption,
overline, bodyBold) in app_typography.dart.

Tokens (design_tokens.dart): spacing (xs/sm/md/lg/xl/xxl), radii
(sm/md/lg/full), durations (fast/normal), 900 px breakpoint, soft card
shadows + glow shadows for urgency.

Motion: subtle only — flutter_animate fades/scales on cards, fast
AnimatedOpacity for completion states, page-level transitions. No bouncing
or looping animations.

Accessibility: tooltips on icon actions, semantic icons accompany colors
(deadline = icon + label + red, never color alone), ≥ 22 px touch targets,
FittedBox/ellipsis to prevent overflow, contrast checked in both themes.

9. REMINDERS (scope decision)
================================================================================

ReminderService builds a complete, preference-filtered reminder plan:
  • Deadlines: 7 / 3 / 1 days before + on the day (sparse by design)
  • Portal openings: one notification on the opening day
  • Meetings: one the day before
Settings previews the next scheduled reminders. Actual push delivery is
deliberately not wired: Android 13+ needs POST_NOTIFICATIONS runtime
permission and flutter_local_notifications + timezone setup. The service is
structured so delivery is a small, documented follow-up (see the header of
lib/services/reminder_service.dart).

12. DESIGN DECISIONS & MIGRATION NOTES
================================================================================

  • Official data is CODE, not storage: users mark things complete; they
    can never corrupt the official definitions. Storage holds only user
    state.
  • Milestone completion ≠ project completion: the UI keeps them as two
    separate, clearly-labeled numbers.
  • Special week labels (Dashain Holiday, Non Teaching Week) are resolved
    exactly like the source sheet — never auto-numbered.
  • Old Student Hub data (class sessions) was not migrated — the domains
    don't map.
  • Notifications: plan-builder implemented; delivery documented as the
    single remaining step (dependency + permission).
  • Responsive: one shell, two navigation modes; calendar adapts columns;
    no fixed-width text containers.
