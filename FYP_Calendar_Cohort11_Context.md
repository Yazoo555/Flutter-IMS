## 5. Event Type Taxonomy (for the app's data model)

Based on the color-coding and content patterns, events fall into these categories.
An application built from this data should likely support filtering/sorting by
these categories:

| Category | Examples | Suggested Priority Level |
|---|---|---|
| **Deadline** (submission due) | Title Submission, Proposal Deadline, Milestones 2–7, Resit Submission | 🔴 Critical / Highest urgency |
| **Assessment / Defense event** | Proposal Defense, Internal Project Defense, Poster Presentation/Viva | 🔴 High (mandatory attendance, graded) |
| **Board / Results** | Board — Result Publication (x2) | 🟠 High (informational but important) |
| **Portal Opening** | "Portal for submission of X will be available from this day" | 🟡 Medium (prep window start — actionable but not itself a deadline) |
| **Google Form Open/Close** | Title submission form, project-specific session form | 🟡 Medium |
| **Session / Lecture / Workshop** | FYP Intro, Workshop/Lecture, Session on Literature Review, etc. | 🟢 Medium-low (recommended attendance, informational/instructional) |
| **Supervisor-related session** | Supervisor Allocation, MST Creation, Session with Supervisor and Reader, "Start of Supervisor Session" | 🟢 Medium (ongoing supervision touchpoints, not single-day) |
| **Holiday / Non-teaching period** | Dashain Holiday, Non Teaching Week | ⚪ Informational only — no action required |

**Relationship pattern to note:** Nearly every Milestone deadline is preceded by a
**Portal Opening** event roughly 9–10 days earlier (explicitly stated in the sheet
as "[X days prior]"). This is a recurring structural relationship the app could
model explicitly (e.g., each Milestone object has a `portal_opens_on` date and a
`deadline_on` date).

## 6. Key Preparation Notes & Warnings (verbatim context from the sheet)

These are important process notes embedded in the sheet (mainly around the
proposal stage) that a student needs to be careful about:

1. **Before writing the proposal:** it's advisable to talk to the allocated supervisor first — especially useful if still undecided on the exact project title.
2. **Proposal approval gate:** Before the Proposal Submission deadline (2026-09-25), the proposal must be reviewed and **approved by the supervisor**. Approval is tracked via a **Proposal Feedback Sheet**. The student should keep getting feedback and revising until the supervisor approves.
3. **PRF (Project Registration Form):** Once the proposal is approved, the student must fill out the PRF and submit it through the designated portal (portal opens 2026-09-18, 9 working days before the 2026-09-25 deadline).
4. **Internal Project Defense readiness requirement:** By the Internal Project Defense window (2027-04-18 to 2027-04-23), the project should be **at least 75% complete**.
5. **Portal lead times:** Submission portals for each milestone consistently open roughly 9–10 days before the corresponding deadline — students should use this window, not wait until the deadline day.
6. **Holiday awareness:** A large ~5.5-week teaching gap (Dashain Holiday) occurs from 2026-10-11 to 2026-11-16, directly after the Proposal Defense — students should plan literature review work accordingly, since the next major session isn't until 2026-11-23.
7. **Non-teaching weeks in December** (2026-12-07, 12-14, 12-21) overlap with the run-up to the Milestone 2 deadline (2026-12-25) — the portal still opens and the deadline still applies during this "break" period.

## 7. Suggested App Features (mapped to the user's stated goals)

To support the user's goals directly from this data:

- **Timeline / calendar view:** render all events from Section 4 on a calendar, using Section 5's category colors for quick visual scanning.
- **Upcoming events / deadlines view:** sort all "Deadline", "Assessment", and "Board" category events by date; highlight the next unmet deadline relative to today's date.
- **Milestone tracker:** use the Section 3 table as a checklist (7 milestones + 2 earlier gates + conditional resit), each with a status (not started / in progress / submitted) and a countdown to its deadline.
- **Priority / urgency flags:** use the priority levels in Section 5 to badge items (e.g., red badge for deadlines and defenses, yellow for portal openings, green for optional sessions).
- **Portal-opening reminders:** since portals open ~9–10 days before each deadline, the app could auto-generate a reminder notification on each portal-opening date pulled from Section 4.
- **Holiday-aware planning:** grey out or visually de-emphasize the Dashain Holiday and Non-Teaching Week periods (Section 4) so the student doesn't mistake them for active teaching time, while still showing that milestone prep work continues.
- **Search/navigation:** allow filtering by month, by week number (Week 1–50), or by event category.
